## Readest

- GitHub 地址：https://github.com/readest/readest
- 项目官网：https://readest.com（网页版：https://web.readest.com）
- 项目分类：阅读与文档工具 / 效率与生产力
- Star 数量：25,985（查询于 2026-11-06）
- 最近更新时间：2026-11-06（仓库创建于 2024-10-12，累计 3,694 次提交、109 个 Release）
- 开源许可证：AGPL-3.0
- 开发语言：TypeScript（Next.js 16 + Tauri v2）
- 支持平台：macOS、Windows、Linux、Android、iOS、Web

### 1. 它是什么？（通俗易懂）

Readest 是一款现代化的开源电子书阅读器，可以理解为 Foliate 的现代化重写版。它不只是一个看书的壳，而是一个带书库管理、标注同步、翻译朗读的完整阅读工作台，一次安装就能在电脑、手机和网页之间接续阅读。

### 2. 它能解决什么问题？（实际场景与痛点）

- 电子书散落在电脑、手机、平板各处，阅读进度和批注互不同步。
- 技术类电子书、论文里的代码没有语法高亮，读起来费劲；外文书查词、翻译要来回切换软件。
- 想在网页上直接读本地书、或者把网页文章/网络小说章节收进书库，没有顺手的开源工具。
- 之前用过 KOReader 等设备的用户，换平台后进度和笔记难以迁移。

### 3. 核心功能（3-5 个）

- **全格式支持**：EPUB、PDF、MOBI、KF8（AZW3）、FB2、CBZ、TXT、HTML、Markdown，技术文档直接用 Markdown 读。
- **跨平台同步**：书库文件、阅读进度、笔记和书签可在 macOS、Windows、Linux、Android、iOS、Web 间同步；还支持与 KOReader 设备同步进度和批注。
- **翻译与朗读**：划词查词典/维基百科，支持 DeepL、Yandex 整句乃至整本翻译；内置多语言 TTS 朗读和 EPUB 3 媒体叠加跟读。
- **双书对照与剪藏**：分屏并行读两本书；可从浏览器剪藏网页、从网络小说导入章节和图片。
- **阅读辅助**：全文检索、高亮批注、代码语法高亮、阅读标尺、逐段阅读、速读模式，支持 OPDS / Calibre 书库接入。

### 4. 为什么值得推荐？（亮点、设计思路、同类优势）

- 与 KOReader、Calibre 相比，Readest 的界面是现代 Web 技术栈（Next.js + Tauri），上手没有学习成本，同时保留了与这两个老牌工具的互通能力，不用在生态和体验之间二选一。
- 完成度很高：上线两年、109 个 Release、每周都有更新，不是昙花一现的 Demo 型项目。
- 把“读技术书”当成一等公民：Markdown 直读、代码高亮、双书对照，这些细节明显是为爱读书的开发者设计的。
- 有网页版可零安装体验（web.readest.com），先试再装。

### 5. 如何使用？（安装、部署或快速体验入口）

- 最快体验：打开 https://web.readest.com 直接在网页上读。
- Windows / Linux：去官网 https://readest.com 或 GitHub Releases 下载安装包；Linux 也可从 Flathub 安装。
- macOS / iOS：App Store 搜索 Readest 安装。
- 注意：Windows 首次启动无反应时，通常是缺少 Edge WebView2 运行库，按 README 的 Troubleshooting 一节安装即可。

### 6. 适合什么人？（普通用户、开发者、学生、技术爱好者）

- 经常读电子书、技术文档和外文书的学生和开发者；需要在多设备间同步阅读进度的重度读者；用 Obsidian / Calibre 管理知识库、希望阅读环节也开源可控的人。

### 7. 推荐指数（实用性、完成度、维护情况、探索价值综合判断，给等级及理由）

★★★★★（5/5）。功能完整、跨平台同步是真需求、两年持续高频维护、109 个 Release 背书，首期最稳的“装了就用得上”的选择。

## img2threejs

- GitHub 地址：https://github.com/img2threejs/img2threejs
- 项目官网：https://img2threejs.io（在线演示画廊，无需安装即可查看生成效果）
- 项目分类：可视化与创意 / AI 与智能体
- Star 数量：20,352（查询于 2026-11-06）
- 最近更新时间：2026-11-06（仓库创建于 2026-07-15，累计 120 次提交、8 个 Release；徽章显示当前版本 v2.0.1）
- 开源许可证：Apache-2.0
- 开发语言：Python（流程编排与校验脚本）+ TypeScript（生成的 Three.js 模型代码）
- 支持平台：Web（生成结果运行于浏览器）；使用时需要 Node.js ≥ 18、Python ≥ 3.10，以及 Claude Code、Codex、OpenCode 或 Hermes 其中一种 AI 编程智能体

### 1. 它是什么？（通俗易懂）

img2threejs 是一个“图片转 Three.js 模型”的 AI 智能体技能（skill）。给它一张物体的参考图，它不会去抠网格、做摄影测量，而是让 AI 一步步写出纯代码的 Three.js 模型——用几何体、程序化着色器和生成的几何结构把图里的物体重建出来，生成的是带层级结构（关节点、插槽、碰撞体）、可以直接拿去做动画的 `THREE.Group`，而不是一团静态网格。

### 2. 它能解决什么问题？（实际场景与痛点）

- 做 Three.js 项目缺模型：网上找现成模型要么版权不明、要么风格不搭，自己建模又不会 Blender。
- 传统图片转 3D 工具输出的是笨重的网格文件，改不了材质、做不了动画，塞进项目里像个黑盒。
- 用 AI 直接“画”3D 容易翻车：比例失真、细节丢失、生成一次就定型，没法迭代。
- 想把参考图里的某个具体物件（比如一把吉他、一个游戏角色）变成可交互的 3D 场景元素，没有低成本的办法。

### 3. 核心功能（3-5 个）

- **分阶段雕刻流水线**：按 blockout → 结构 → 形态 → 材质 → 表面 → 光照 → 交互 → 优化逐步生成，每步都有视觉评审和自我修正。
- **质量门禁**：生成前先枚举“细节清单”（光泽、倒角、螺丝、刻线、磨损等），清单不完整就阻止生成；材质按区域裁剪分析、对照 Three.js 材质注册表、逐区域比对验收。
- **Token 高效**：确定性 Python 脚本负责校验和门禁，模型 token 只花在视觉判断和写代码上，不浪费在重复劳动里。
- **角色与多视角支持**：角色走解剖学管线（头身比、面部特征点、姿态）；可选多视角剪影雕刻，用至少两个正交剪影求交得到体素网格，未见区域明确标记为低置信度而不是凭空编造。
- **插件化领域扩展**：CS2 武器、角色绑定、动画角色等领域插件按需安装，另有在线演示画廊可直接查看吉他、Groot、星舰等生成实例的源码。

### 4. 为什么值得推荐？（亮点、设计思路、同类优势）

- 思路上反直觉但正确：不追求“像照片”，而是追求“像代码”——输出是人类可读、可改、可复用的 Three.js 源码，这对学习者来说比任何模型文件都有价值。
- 诚实是这个项目的招牌：README 专门有一节“Honesty about limits”，承认单张图无法保证 100% 相似度，低置信度区域会明说、会要求补视角。
- 与“图片转 3D 网格”类工具是不同赛道：它解决的是“把参考变成能写进项目的 3D 代码”，对正在做 Three.js 项目的人是直接可用的生产力。
- 上线不到 4 个月拿到 2 万 Star，且仍在快速迭代（最新 v2.0.1），是近期 Three.js 社区最受关注的新项目之一。

### 5. 如何使用？（安装、部署或快速体验入口）

- 先看效果：打开 https://img2threejs.io 的演示画廊，任意模型都能在线旋转查看、对照原图、阅读生成的源码，零安装。
- 自己动手：需要 Node.js ≥ 18、Git、Python ≥ 3.10 和一个 AI 编程智能体（Claude Code / Codex / OpenCode / Hermes），执行 `npx --yes img2threejs@latest install` 安装技能，重启智能体后附上一张参考图并输入 `/img2threejs Rebuild the object in ./reference.png as a procedural Three.js model.` 即可开始重建。详细步骤见仓库 `docs/INSTALL.md`。
- 注意：重建过程会消耗所用智能体的模型调用额度；效果取决于参考图质量和模型能力，复杂角色建议先从画廊里的简单物体示例入手。

### 6. 适合什么人？（普通用户、开发者、学生、技术爱好者）

- 正在学 Three.js / 做 3D 智慧园区、数字孪生等项目的学生和开发者；想给网页加 3D 元素的前端开发者；对“AI 写 3D 代码”这一思路感兴趣的技术爱好者。

### 7. 推荐指数（实用性、完成度、维护情况、探索价值综合判断，给等级及理由）

★★★★☆（4/5）。创意和思路都是本期最亮眼的，对 Three.js 学习者的启发价值极大；扣一星是因为使用门槛不低（需要 AI 编程智能体并消耗额度），且生成质量依赖模型能力，不适合当作开箱即用的傻瓜工具。

## oh-my-pi

- GitHub 地址：https://github.com/can1357/oh-my-pi
- 项目官网：https://omp.sh
- 项目分类：AI 与智能体 / 开发者工具
- Star 数量：37,965（查询于 2026-11-06）
- 最近更新时间：2026-11-06（仓库创建于 2025-12-31，累计 678 个 Release）
- 开源许可证：MIT
- 开发语言：TypeScript + Rust（约 8 万行 Rust 核心），Bun 运行时
- 支持平台：macOS、Linux、Windows（终端 TUI）；另提供 Node SDK、RPC 与 ACP 编辑器协议接入

### 1. 它是什么？（通俗易懂）

oh-my-pi（简称 omp）是一款终端里的 AI 编程智能体，由 Stencil Labs 在 Mario Zechner 的开源 Pi 基础上分叉开发。通俗讲，它是“把 IDE 的本事装进终端智能体”：改代码之前先懂你的项目结构，改完能自己跑调试器验证，还能像结对编程一样把会话分享给别人。

### 2. 它能解决什么问题？（实际场景与痛点）

- 普通 AI 编程助手改代码常“想当然”：重命名漏改引用、移动文件不管 re-export，改完还得人肉收尾。
- 调 bug 只能靠 print：C 程序段错误、Go 服务 hang 住、Python 进程卡死，助手给不出比日志更深的信息。
- 换模型、换服务商就要换工具；不同厂商 API、本地模型、OpenAI 兼容接口之间来回折腾。
- 一个人写代码、想让别人实时看到智能体的操作或一起改，缺乏顺手的共享方式。

### 3. 核心功能（3-5 个）

- **LSP 接入每一次写入**：重命名、移动文件走 IDE 的语言服务器协议，引用、re-export、别名导入一起更新；14 种 LSP 操作开箱即用。
- **会驱动真正的调试器**：能挂 lldb 调 C 程序、dlv 跟 Go 协程、debugpy 暂停 Python 进程并检查变量，而不是只会加打印语句。
- **多模型与多厂商**：60+ 服务商、上千个模型，一条 `/model` 命令切换；支持 Frontier API、Coding Plan、本地自托管模型和自定义 OpenAI 兼容服务商。
- **子智能体与审查模型**：任务可分发给带类型化结果的子智能体并行处理；可配一个“顾问模型”逐回合审查主智能体的操作，发现问题当场提醒纠正。
- **协作与可扩展**：`/collab` 生成链接或二维码，他人可在浏览器围观或加入同一会话；支持 ACP 协议供编辑器驱动，GitHub 可当作文件系统直接读写，23 种搜索后端开箱即用。

### 4. 为什么值得推荐？（亮点、设计思路、同类优势）

- 与 Claude Code、Codex 等相比，omp 的差异化很实在：LSP 和调试器是“IDE 才有的能力”，把它做进终端智能体，意味着它改代码的准确率不是靠提示词堆出来的，而是靠工具链保证的。
- 工程投入看得见：约 8 万行 Rust 核心专门做“别的工具外包给 shell 的活”，31 个内置工具、28 种 DAP 调试操作，这种体量在同类开源项目里少见。
- 完全开源（MIT）、多厂商中立，不绑定某个模型服务商，对学生和独立开发者友好；且有中文 README（README.zh-CN.md）。
- 演进速度极快：678 个 Release，基本保持着每天多更的节奏。

### 5. 如何使用？（安装、部署或快速体验入口）

- macOS / Linux：一行安装 `curl -fsSL https://omp.sh/install | sh`（无可用 bun 时会自动拉取预编译二进制并校验 SHA-256）。
- Windows（PowerShell）：`irm https://omp.sh/install.ps1 | iex`。
- 也可用 Homebrew（`brew install can1357/tap/omp`）、Bun（`bun install -g @oh-my-pi/pi-coding-agent`）或 Nix（`nix run github:can1357/oh-my-pi`）。
- 安装后在终端输入 `omp` 进入交互界面；使用前需配置至少一个模型服务商的 API Key（支持 60+ 服务商，也可接本地模型）。

### 6. 适合什么人？（普通用户、开发者、学生、技术爱好者）

- 每天写代码、想用 AI 提效的开发者和学生；对 Agent 内部机制（LSP、DAP、子智能体、ACP 协议）感兴趣、想读源码学实现的人；不满足于“聊天式改代码”、想要更可靠的编程助手的人。

### 7. 推荐指数（实用性、完成度、维护情况、探索价值综合判断，给等级及理由）

★★★★☆（4/5）。功能密度和工程完成度在同类终端智能体里属于第一梯队，LSP + 真调试器是实打实的差异化；扣一星是因为项目迭代极快、部分高级功能仍在快速变化中，且需要自备模型 API Key，有一定上手和费用门槛。
